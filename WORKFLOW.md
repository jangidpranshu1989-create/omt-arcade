Development Workflow

1. Before Making Changes

- Navigate to the project directory.
- Inspect existing files before editing.
- Keep the current game logic and working features intact.

2. Development Rules

- Work on one feature at a time.
- Keep the UI responsive on mobile and desktop.
- Avoid unnecessary dependencies.
- Test game controls, scoring, restart buttons, and navigation.
- Do not claim a game works until it has been tested.

3. Testing

- Open the website in a browser.
- Test each changed feature.
- Check the browser console for errors.
- Verify mobile layout and keyboard controls where applicable.

4. Git Workflow

- Review changes before committing.
- Use clear commit messages.
- Never commit API keys, passwords, tokens, or private credentials.
- Do not overwrite unrelated project files.

5. Project Goal

Build One More Try into a polished, accessible browser-game arcade with original experiences, reliable game logic, and a professional user experience.
